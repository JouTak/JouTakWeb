# Игроки, подписки и контакты

Локальное расширение Hub по запросу от 21.09.2026. Живёт в существующем
`profiles`; аккаунты, аутентификация и городские роли не меняются. Rollout —
существующий `community_profiles_ui`, без новой системы уведомлений/чата.

- `/players`: поиск по username/display_name и разрешённому Minecraft nick;
  фильтр «Мои подписки», pagination 24, сортировка имя/username/id.
  Карточка показывает аватар, разрешённый Minecraft-ник (или логин) и доступные статусы «Город — должность/роль»
  компактными бейджами с мягкой заливкой и рамкой, как в референсе. Бейджи
  переносятся на следующую строку и сохраняют ссылку на город.
  Bio, повторный Minecraft nick и display name в каталоге не выводятся. Поиск
  по этим разрешённым полям сохраняется. `PlayerOut.cities` — компактные typed
  данные slug/name/role/position; общий профильный и городской visibility policy.
  Только ACTIVE membership/city/community. Страница из 24 игроков с городами
  загружается четырьмя запросами, без запроса на каждого игрока.
- `/u/:username`: подписаться/отписаться, контакты, ссылка «Поделиться профилем»,
  карточка стажа и две карточки «Подписчики» / «Друзья» с числами и сетками
  аватаров-ссылок. Вкладок «О человеке / Круг общения» больше нет.
- Account shortcuts ведут к поиску и личным подпискам. Контакты редактируются
  отдельным коротким диалогом в настройках профиля.
- Гости открывают профиль по аватару и имени, без отдельной кнопки. Призывов войти и подписаться
  нет ни в карточках, ни в профилях; подписка доступна после авторизации.
- ProfileFollow(user → target): направленная связь, unique pair, DB no-self,
  CASCADE при удалении аккаунта. Повторный follow/unfollow идемпотентен.
  Подписка не расширяет доступ и не даёт никаких city/community permissions.
- ProfileContact: unique(user, type), Discord/Telegram/VK, value, visibility.
  Нет email/телефона/ISU; legacy VK не копируется и не публикуется автоматически.
  Telegram/VK принимают имя или проверенный URL провайдера; Discord — username
  или URL профиля. Сервер возвращает безопасную canonical URL либо только текст.
  Явно заданный VK-контакт, включая закрытый, имеет приоритет над legacy VK;
  публичный fallback не обходит выбранную видимость.
- Поиск фильтрует profile visibility до пагинации/подсчёта. По закрытому nick,
  контактам, email/ИСУ искать нельзя. COMMUNITY требует общей ACTIVE community.
- `connections_visibility` по умолчанию PRIVATE. Личная подписка доступна самому
  подписчику. Публичный исходящий список требует видимости связей владельца;
  входящий список дополнительно показывает только подписчиков, открывших свои
  связи. Имена в любом списке проходят текущую видимость профиля. Подсчёт касается
  только доступных зрителю результатов. Закрытие профиля скрывает его из поиска
  и списков; существующая подписка не обходит ограничение.
- API: GET /profiles/players; GET /profiles/public/{username}/connections;
  POST/DELETE /profiles/public/{username}/follow; GET/PATCH /profiles/me/contacts.
  Contact replacement atomic; typed bounded inputs and existing session auth.
  Follow/contact mutations share per-account rate limiting (60/h).

Проверки: приватные nick не влияют на результаты, shared-community suspension,
no self/duplicate follows, guest mutation denial, скрытие после смены visibility,
private follows/contact отсутствие в public schemas, unsafe provider URLs,
pagination/query-count bound, deletion cascade, legacy migrations. UI: поиск,
переходы, follow/unfollow, ошибки, clipboard fallback, контакты и mobile layout.

## Друзья и стаж (21.09.2026)

`GET /api/profiles/public/{username}/connections?direction=...` принимает:

- `following`: все исходящие подписки, включая взаимные (совместимость).
- `followers`: только невзаимные входящие подписки.
- `friends`: пересечение входящих и исходящих подписок. Отдельной таблицы дружбы
  нет; ответная подписка переносит человека в друзей, отписка отменяет взаимность.

Списки друзей и подписчиков используют одинаковые ограничения видимости профиля
и связей обеих сторон. Число относится только к доступным зрителю профилям;
закрытый список показывается без числа. Дружба не расширяет доступ к закрытым
полям и не меняет community/city permissions. Пагинация по 24, пять DB-запросов
на публичную страницу друзей вместе с разрешёнными городскими данными, без N+1.
После follow/unfollow обе карточки перечитываются. Каждая независимо обрабатывает
loading/error/retry/empty, аватары доступны с клавиатуры и имеют название профиля.

`profiles/0004` добавляет `CommunityProfile.minecraft_first_joined_at`.
По явному решению пользователя все существующие и новые профили получают общую
дату по умолчанию **01.01.2026**, без пометок в интерфейсе. Это согласованная
начальная дата, а не подтверждённое событие Minecraft и не дата регистрации на
сайте. Источника серверных событий пока нет; будущий импорт должен заменить
значение реальной датой. Self-profile API не позволяет менять это поле; admin
показывает его только для чтения. Создание необязательного community profile
для старого аккаунта не становится условием входа или onboarding.

`PublicProfileOut.server_history` содержит `first_joined_on`, `days`, `days_text`.
Видимость наследуется от Minecraft-данных. Дни — календарная разница в настроенной
Django timezone, а не время активной игры. Будущая дата не даёт отрицательный стаж.
Склонение «день/дня/дней» делает `pymorphy3` (`make_agree_with_number`); словарь
загружается лениво один раз на процесс. Frontend форматирует дату, но не считает
стаж и не дублирует русскую морфологию.


## Minecraft-ник как основное имя

Публичные карточки, администрация и жители города, сетки друзей/подписчиков,
личный кабинет и account avatar используют единый `getPlayerName`: разрешённый
Minecraft-ник → логин → «Участник сообщества». Имя/фамилия не используются даже
в alt/tooltip вне самого профиля. В профиле имя остаётся вторичной строкой под
ником; повторяющее его значение не выводится. Подпись стажа сокращена до
«с 01.01.2026» с календарной датой в `time[datetime]`.

Nick приходит из существующей backend visibility policy. Закрытый Minecraft-ник
или закрытый профиль не раскрывается управляющему города через дополненные
`MemberOut`/`InvitationOut`; административный список сохраняет доступный ему
логин аккаунта. Общие сообщества аннотируются в SQL, связанные профили загружаются
одним join. Четыре запроса на страницу management roster (с прогретыми Django
permissions); два на страницу приглашений, без запросов на каждого игрока.

URL профиля, follow/unfollow, приглашения и изменение членства по-прежнему
используют стабильный username/id. Minecraft-ник — отображение, а не ключ
авторизации или новая сущность аккаунта. Существующие разрешения не меняются;
изменения API additive, новых миграций нет.


## Компактная сетка профиля

Под шапкой desktop layout разделён на основную часть 9/12 и контакты справа 3/12.
Стаж, подписчики и друзья показаны одним рядом компактных карточек высотой от
80 px; число расположено рядом с названием без крупного отдельного счётчика.
Аватары 36 px остаются под карточками, пагинация и независимый retry сохранены.
Пустой доступный список показывает ноль, закрытый — «Список скрыт» без числа.
На ширине до 1000 px контакты переносятся под статистику перед членством; до
700 px стаж и две социальные карточки занимают отдельные ряды. Контакты остаются
частью обычного потока страницы и не перекрывают контент при прокрутке.
