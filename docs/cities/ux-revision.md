# Hub: переработка по пользовательскому просмотру, 21.09.2026

## Принятые изменения

- Кабинет — короткий вход в мои города, сообщества и приглашения. Профиль —
  отдельная страница человека; пункт «Профиль» открывает её, а не настройки.
- Одна глобальная шапка. Настройки профиля и безопасность не повторяют навигацию
  кабинета. В безопасности нет карточки персонализации и дубля профиля.
- Сообщества — клубы по интересам. Города показываются в отдельном разделе
  кабинета и в пространстве ItmoCraft. Связь City → Community в БД сохраняется.
- Карточка моего города: знак/логотип, название, одна должность. Без «активного
  участия», повторения ItmoCraft, технических ролей и форм видимости.
- Страница города: обзор и жители; история доступна редакторам отдельной
  вкладкой и загружается только при открытии. Контакты и карта рядом с обзором.
- Редактирование отдельных разделов в контексте страницы. Короткие диалоги,
  предпросмотр Markdown, загрузка изображений. Язык и map_id скрыты из UI.
- Местоположение: координаты X/Z (Y — высота, необязательно) либо проверенная
  ссылка BlueMap. Сервер разбирает ссылку без сетевого запроса к ней.
- Новые контакты ограничены Discord-приглашениями, Telegram и VK; провайдер и
  адрес проверяются сервером. Ранее сохранённые ссылки не теряются.
- Менеджер приглашает, адресат принимает/отклоняет в кабинете. До согласия нет
  членства и прав. Принятие всегда даёт роль жителя; повышение — отдельное
  авторизованное действие. Приглашения можно отозвать, они истекают через 14 дней.

## Границы и совместимость

Новых глобальных ролей, произвольных схем страниц, конструктора блоков и общей
системы уведомлений не вводим. Уведомление о приглашении — список в кабинете.
Первичное назначение управляющего при создании города остаётся отдельной
модераторской операцией; обычное добавление жителей через API заменяется
приглашениями. Старые адреса /account/profile и /cities/:slug/manage сохраняются.
Архив и тестовые QA-города не показываются в обычных карточках кабинета;
история сохраняется для модерации. Удаление данных для косметического исправления
не используется.

Границы, площади и синхронизация маркеров BlueMap требуют отдельного источника
данных и сопоставления городов с регионами. Не выводим вычисленные площади и не
запускаем периодический импорт без этого контракта. Это следующая итерация.

## Проверка

Проверяем согласие/отказ/отзыв/повторное принятие приглашений, IDOR, истечение и
архивацию города до принятия; отсутствие повышения роли при принятии; безопасные
контакты, изображения и map URL. UI: один header, профиль из меню, короткие
редакторы, неизменённые права, история по запросу, мобильный вид и отсутствие
несохранённой потери данных. Затем пересобираем только локальные demo-контейнеры.

## Реализовано и проверено

Все перечисленные изменения реализованы локально, с миграциями приглашений и
media references. Действующие feature flags сохраняются; публичный rollout
не выполнялся. `/cities/:slug/manage` сохранён как вход в контекстный редактор.
Безопасность не содержит персонализацию; её прежние API и MFA остаются прежними.
Auth fallback различает гостя, MFA и временную ошибку сервера; safe next сохраняет
путь/query/hash и отвергает внешние адреса.

В браузере проверены принятие приглашения, обновление роли/счётчика, audit,
изображение из файла, ссылка BlueMap, dirty-close и мобильный экран. Полный список
проверок и ограничений — [implementation-report.md](implementation-report.md),
сценарии и personas — [rollout.md](rollout.md).

## Карточки каталога

В `/cities` крупный логотип занимает левую часть карточки. Название и логотип
открывают город; отдельной ссылки «Подробнее» и повторения ItmoCraft нет.
Сверху — статус набора и иконка BlueMap, ниже — название, должность и Minecraft-ник
управляющего, разделитель «·» и число игроков с правильным склонением.

`GET /api/cities` дополнен typed `leader` (username, minecraft_nick, position) и
`map_url`. Управляющий выбирается только среди активных manager memberships
активных участников сообщества; должность «Мэр» определяет приоритет отображения,
но не даёт прав. При нескольких управляющих выбор детерминирован. Видимость
профиля, Minecraft-ника и обеих настроек членства проверяется той же policy, что
на странице города. Закрытый управляющий не выводится; реальные имена, email
и другие приватные поля в новый объект не входят. Каталог использует три
DB-запроса для гостевой страницы независимо от количества городов (без count
и feature flags); для авторизованного зрителя дополнительно загружает его
сообщества одним запросом.

Map URL строит существующий backend adapter. Без координат или при выключенном
`cities_map_integration` иконки нет. Ссылка открывается в отдельной вкладке с
`noopener noreferrer`; frontend дополнительно отклоняет небезопасные URL.
База данных и существующие названия городов не изменяются, миграции не нужны.
