# Локальная проверка и включение объединений

Работа ведётся в текущем локальном изменении Community Hub. Ничего не отправляется
в GitHub или production. Существующий demo доступен на `http://127.0.0.1:5174`.

## Флаги и миграции

- Additive `communities.0002`: необязательные инструкции вступления в сервер.
- `playergroups.0001`: отдельные модели объединений, согласия, ограничений и аудита.
- Новые `player_groups_ui`, `player_groups_write` по умолчанию false; требуется
  также прежний `communities_ui`. Флаг записи отдельно останавливает действия,
  сохраняя доступное чтение. API проверяет флаги напрямую.
- BFF доставляет флаги, без загрузки полного состава/каталога в глобальный shell.
- Реестр обновляется `sync_feature_registry`; затем staff/allowlist, beta и public.
- Откат включения: выключить write, затем UI. Не откатывать миграции с реальными
  данными: удаление нового app удалит его историю. Старые профили/серверы/города
  миграциями не переписываются.

Параметры лимитов в `.env.example`: создание 5/сутки, заявки 20/сутки,
приглашения 50/сутки; предложения/приглашения 14 дней, заявки 30 дней,
повторное приглашение после отказа через 7 дней. Это DB-backed проверки под
блокировкой аккаунта, не клиентские ограничения.

## Демо

```bash
python backend/manage.py migrate --settings=backend.settings.hub_demo
python backend/manage.py seed_player_groups_demo --settings=backend.settings.hub_demo --enable
docker compose -f compose.hub-demo.yaml up -d --build --wait
```

Команда работает только с отдельной `.local/community-hub.sqlite3`, требует
прежние Hub personas и не сбрасывает их пароли, изображения или содержимое.
Повтор не меняет существующие группы и не создаёт заново обработанные предложения.
Перед upgrade сохранён backup `.local/backups/before-player-groups-20260921.sqlite3`.
Не используйте команду для production seed.

| Аккаунт | Сценарий |
| --- | --- |
| Гость | Видит серверный раздел и публичные клубы, не видит управление/private/draft/archive |
| hub_manager | Руководит «Мастерской строителей» и «Северной экспедицией», разбирает заявки |
| hub_resident | Участник мастерской, ожидающая заявка в экспедицию и предложение руководства |
| hub_representative | Модератор мастерской, личное приглашение в «Редстоун-кружок», черновик «Картографы» |
| hub_moderator | Отдельное платформенное разрешение, обзор и восстановление управления |

Прежние данные входа находятся в локальном `.local/demo-access.txt`; команда не
публикует и не меняет их. «Вечерняя стройка» показывает unlisted-сценарий;
«Летний проект» архивирован и доступен через личную историю/модерацию.

## Ручная QA

1. `/communities`: серверы отдельно от клубов. Найдите мастерскую; проверьте фильтры
   и пустой результат. Вкладка браузера/назад сохраняет фильтры в URL.
2. Гость: `/groups/builders-workshop` читается. `/groups/redstone-circle` возвращает
   нейтральное недоступное состояние. `/groups/evening-build` открывается по ссылке,
   но в каталоге отсутствует. Кнопок управления у гостя нет.
3. `hub_resident`: `/account/communities` показывает заявку и предложение руководства.
   Отказ не меняет членство; принятие меняет роль только после клика. Повторное
   действие не создаёт вторую запись. Личная видимость по умолчанию закрыта.
4. `hub_representative`: личный inbox показывает краткое приглашение в закрытый
   кружок. До принятия полная страница/контакты недоступны; после — доступны.
   В мастерской доступны редактор и заявки, но не назначение руководителей/условия.
5. `hub_manager`: `/groups/northern-expedition/manage?tab=queue` → принять или
   отклонить заявку. Решение видно адресату. В составе можно назначить модератора,
   предложить управление или передать своё с согласием получателя.
6. Попробуйте выйти последним руководителем: отказ с объяснением. Измените страницу
   из двух вкладок: устаревшая версия не затирает свежую, введённый текст остаётся.
7. В условиях участия выключите набор: принятие старых приглашений/заявок недоступно,
   отказ/отзыв/выход доступны. Архив закроет процессы, восстановление оставит паузу.
8. Завершение участия не запрещает rejoin. «Ограничить участие» запрещает его;
   снятие ограничения само не возвращает членство или прежнюю роль.
9. `hub_moderator`: `/moderation/groups` → история/основание ограничения. Для
   восстановления укажите подходящий профиль; получатель должен согласиться.
10. Проверьте public/members/private для состава и личного участия. В закрытом
    составе нет общего счётчика. Ни дружба, ни общий клуб не раскрывают поля,
    видимые только участникам официального сервера. Email/ISU нигде не появляются.
11. Откройте профиль, город, безопасность и персонализацию старого пользователя:
    прежние связи и введённые сведения сохраняются. Ширины: 320, 390, 768, 1440;
    клавиатура: фильтры, формы, диалоги, возврат фокуса.

## Проверки для повторного запуска

```bash
uv run ruff check .
uv run bandit -r backend/playergroups backend/communities backend/profiles backend/accounts backend/backend -x '*/tests/*,*/migrations/*' --skip B104,B105
PYTHONPATH=backend DJANGO_SETTINGS_MODULE=backend.settings.dev uv run python scripts/check_frontend_openapi_contracts.py
uv run python backend/manage.py makemigrations --check --dry-run
uv run pytest backend -q
npm --prefix frontend run check
npm --prefix frontend run test:e2e -- e2e/player-groups.spec.js e2e/community-hub.spec.js
```

Для конкурентных тестов нужен PostgreSQL и `has_select_for_update`; SQLite их
пропускает. В этой проверке используется отдельный временный PostgreSQL, без
подключения к рабочей БД. Фронтенд проверяет consent, сохранение черновика при
ошибке/конфликте, подтверждение передачи, паузу и отложенную загрузку истории.
E2E проверяет реальные маршруты с контролируемыми API-ответами; backend API/services
отдельно проверяют реальные транзакции и разрешения.
