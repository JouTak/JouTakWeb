# Профили: локальная итерация по двум рекомендациям

21.09.2026. Изменения реализованы в текущем локальном рабочем дереве. Пуша,
удалённого PR и production rollout нет. База демо и существующие пользовательские
изменения сохранены. Источники: [рекомендации первого агента](system-spec-agent-prompt-2026-09-21.md),
[рекомендации второго агента](../user-profile-system-spec-2026-09-21.md),
[принятые решения](adr-001-safe-editing-and-preview.md).

## Что изменилось

- Редакторы описания, приватности и игровых данных отправляют только изменённые
  поля. Сервер атомарно проверяет версию. Ответ 409 сохраняет введённое и позволяет
  загрузить актуальные значения, сравнить их и отдельно подтвердить сохранение.
  Нормализованный ответ становится новым состоянием формы. Сетевой сбой не
  очищает ввод; закрытие несохранённого диалога требует подтверждения.
- Контакты имеют независимую версию списка. После явного сохранения этого списка
  старый VK из аккаунта перестаёт подставляться: удалённый контакт не возвращается.
  До первого сохранения миграция сохраняет прежнюю аудиторию. Private explicit VK
  подавляет legacy fallback. Старое учётное поле остаётся для account/onboarding.
- Гостевой просмотр показывает сохранённую страницу по действительным гостевым
  правилам, включая контакты, связи и клубы. Закрытая страница недоступна гостю.
  API не принимает произвольного зрителя. Unlisted-клубы не раскрываются гостю
  через профиль, а общий клуб и дружба не расширяют серверную аудиторию.
- Владелец видит свою аудиторию и отдельную ссылку на гостевой просмотр. Города
  остаются в компактных пинах без повторного списка; пустые блоки клубов убраны.
- «Мои подписки» позволяет отписаться от недоступного профиля без раскрытия его
  имени, ника или других данных. Удаляется только собственная сторона отношения.
- Minecraft-ник и аватар обновляются в личном интерфейсе после сохранения. False
  в ИТМО теперь означает «Не студент ИТМО», отдельно от отсутствующего значения.
  Редактор Minecraft не отправляет соседние VK/ИСУ/ФИО. При смене зрителя ранее
  загруженные блоки очищаются; черновики не сохраняются между аккаунтами.
- Обновление социальных карточек не сбрасывает страницу списка без необходимости.
  Ошибка копирования ссылки открывает компактное окно с правильным адресом профиля.

Сохранены выбранный пользователем дизайн, серые карандаш и ссылка в шапке,
Minecraft-ник как основное имя, дополнительное имя только в профиле, компактные
стаж/подписчики/друзья, правая колонка контактов и дата 01.01.2026. Новых обязательных
полей регистрации, зависимостей или внешних интеграций не добавлено.

## Контракты и файлы

Основные изменения: `backend/profiles/`, блокировка legacy writer в
`backend/accounts/services/profile.py`, собственный аватар в
`backend/accounts/services/auth.py`, профильная проекция групп в
`backend/playergroups/account.py`. На frontend — `components/profile/`,
`pages/profile/`, `pages/account/AccountProfile.jsx`, профильные API clients,
общие состояния загрузки и небольшое обновление identity в существующих headers.
Навигация отдельной задачи сохранена.

| Endpoint | Назначение |
| --- | --- |
| GET/PATCH `/api/profiles/me` | Собственное представление; partial PATCH с `version` |
| GET/PATCH `/api/profiles/me/contacts` | Эффективный набор контактов с независимой `version` |
| GET/PATCH `/api/profiles/me/game-data` | Узкие приватные игровые/учётные поля с opaque version |
| GET `/api/profiles/me/preview` | Собственный профиль глазами гостя, nullable profile |
| GET `/api/profiles/me/preview/connections` | Гостевые списки друзей/подписчиков |
| GET `/api/profiles/me/preview/groups` | Гостевой список объединений |
| GET `/api/profiles/me/following` | Собственные отношения с nullable identity |
| DELETE `/api/profiles/me/following/{relation_id}` | Удаление только собственного отношения |

OpenAPI остаётся источником схем. Пропущенное PATCH-поле не меняется; явный null
отклоняется; разрешённый текст очищается пустой строкой. Старый локальный frontend
без версии получает 422: обновлять frontend и backend вместе. Прежние account API
совместимы и участвуют в той же блокировке; они сами не требуют нового version token.

Новые routes: `/account/profile/preview`, `/account/profile/following`.
Существующие `/u/:username`, `/account/profile`, onboarding и security сохранены.
Используется прежний `community_profiles_ui`; блок клубов дополнительно зависит
от `communities_ui` и `player_groups_ui`. Новых флагов или env-переменных нет.
Профильные ответы имеют `private, no-store`.

Миграция `profiles.0005_profile_editing_versions` добавляет `version`,
`contacts_version`, `legacy_vk_enabled`; не меняет существующие поля. До её
применения сделана `.local/backups/before-profile-editing-20260921.sqlite3`.
Сравнение старых колонок до/после подтвердило сохранность аккаунтов, UserProfile,
CommunityProfile, контактов, подписок, городов и объединений. Проверка upgrade
с 0004 на 0005 включена в тесты. При откате следует учитывать потерю новых
version/fallback-маркеров; откат миграции не заменяет восстановление backup.

не менялись. В backend остаются предупреждения библиотек о Pydantic Config и
отсутствующем каталоге staticfiles в тестовом окружении.

Браузерные тесты используют контролируемые API fixtures для ошибок/конфликтов;
это дополняет настоящие backend tests, не заменяет их. Проверены ширины
320/390/768/1440, клавиатурный focus и axe для профиля. Первоначальный сбой был
ошибкой тестового селектора: диалог и textarea назывались «О себе».

## Ручная проверка

Демо: <http://127.0.0.1:5174/u/hub_manager>. Persona: `hub_manager` (владелец),
`hub_resident` (другой игрок), `hub_representative`, `hub_moderator` и гость.
Данные входа остаются в локальном `.local/demo-access.txt`; не публиковать их.
Для проверки обновлённой сборки перезагрузить страницу после сохранения своего
незавершённого ввода.

1. Войти как hub_manager, открыть свой профиль. Карандаш ведёт к коротким
   редакторам; рядом остаётся серая кнопка ссылки. Проверить compact layout и контакты справа.
2. Открыть настройки в двух вкладках. В B изменить аудиторию и сохранить, в A
   изменить bio. A показывает конфликт и сохраняет ввод; после сравнения повторное
   сохранение bio не возвращает старую аудиторию.
3. В редакторе контактов удалить VK и сохранить. В гостевом просмотре старый VK
   не появляется. Не использовать реальные приватные контакты для этого сценария.
4. Изменить ник в Minecraft-настройках. Он обновляется в hero и личном меню;
   VK/ИСУ не меняются. Сохранить исходное значение после проверки.
5. Открыть «Посмотреть как гость». Public показывает только разрешённое; private
   и community — сообщение недоступности. Свой настоящий профиль по-прежнему
   показывает собственные данные и аудиторию.
6. Проверить закрытие изменённого редактора по Escape и переход со страницы:
   появляется подтверждение; отказ оставляет ввод. После успешного сохранения
   предупреждения больше нет. Ошибка сети оставляет черновик.
7. Если подписка ведёт на скрывшийся профиль, открыть «Мои подписки» и отписаться.
   Данные скрытой цели не раскрываются, встречная подписка не удаляется.

## Ограничения и следующий этап

Это P0–P1 переданных рекомендаций. Просмотр другой аудитории пока только гостевой;
нет выбора произвольного пользователя или симуляции чужого доверенного контекста.
Загруженные изображения доступны по ссылке независимо от приватности страницы,
о чём сообщает редактор. Замена списка контактов при конфликте требует явного
повторного сохранения. Старые account clients совместимы, но полноценное обнаружение
устаревшей формы обеспечивается новым versioned endpoint.

Отложены P2: проверка владения Minecraft, реальные серверные события/presence,
добавочные интересы и статистика, блокировки, комментарии, репутация, уведомления
и production rollout. BlueMap и структура городов этой итерацией не менялись.
